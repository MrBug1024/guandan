# 掼蛋 AI 竞技场

四个独立 AI 选手、服务端掼蛋裁判、Vue 3 + TypeScript + Vite、Three.js 角色、LangGraph 决策流水线，以及独立的直播观战页面。

## 启动

Node.js 22+，本地使用 Node 24 验证。

```sh
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173/login`。默认管理员账号 `ymtadmin`，初始密码按项目负责人指定值初始化。首次启动建立 `data/admin.json`，之后保持已有账户。

```sh
npm test
npm run build
npm start
```

生产默认端口 3001，`HOST`、`PORT` 可通过环境变量修改。开发和生产服务不要同时占用同一端口。Coolify 使用根目录作为构建上下文、`deploy/Dockerfile` 作为 Dockerfile。

## 管理与分享

- `/login`：管理员登录；`/studio`：管理工作室；`/arena`：管理员对局控制。
- 管理员从直播工作台复制 `/watch/<分享标识>`，或在对局页点击“分享观战”。观众不需要登录，只能观战。
- 观众不能访问管理 API、配置或其他三家手牌。管理员使用 HttpOnly Cookie 会话，旧 CONTROL_TOKEN 已停用。
- 手机自动使用竖屏取景、贴近角色的名称卡片和扇形手牌；显式竖屏可追加 `?layout=portrait`。
- 管理员可以暂停、开始、重新开始。重开立即重新发牌，旧模型返回的动作不会污染新局。

## 模型与 JEV

在模型配置页直接填写 Base URL、模型 ID 和 API Key。保存后不回显 Key，留空保留，填写新值替换，勾选删除清除。配置在后端加密保存，凭证不进入观众状态、前端存储或录像。旧环境变量仅作为现有部署的兼容路径，新配置不需要新增环境变量。

当前使用 `https://model.rhzy.ai/v1`，四个座位分别为桃桃 / MiniMax-M3、蓝莓 / kimi-k2、团子 / glm-5.3-flash、芒果 / gpt-5.6-luna。首次无模型配置时使用四个内置策略。

JEV 是四个选手自主调用的 MCP 辅助工具，不能替代任何选手。模型仅得到自己的手牌、公开局势和合法候选；工具咨询后仍由该模型选择，裁判校验动作。当前 JEV 地址为 `http://10.0.10.2:8019/mcp`，部署服务器必须具有相应内网路由。

## 解说与直播

解说开关及动态面板由服务器广播同步。控制台静音，观众页播放；观众首次点击开启声音以满足浏览器播放限制。

可选择浏览器系统语音，或在管理界面配置支持 `POST /audio/speech` 的音频服务。后者播放实际 MP3，适用于不支持系统语音的微信版本。对局模型不一定支持 TTS，语音模型、音色和凭证需要按服务商实际能力配置并测试。当前未做真实微信设备验收。

OBS 可采集分享页；抖音、快手、视频号使用各自官方直播工具与授权账号。本项目提供画面和解说，不会自行完成平台授权或开播。禁止赌博声明常驻观战画面。

## 部署与数据

必须持久化并成对备份 `data/admin.json` 与加密的 `data/agents.json`。管理员文件包含密码哈希、配置加密密钥和分享标识，不能删除后单独恢复加密配置。更新重启会结束内存比赛，需要重新登录；模型配置、分享链接和录像通过数据目录保留。
