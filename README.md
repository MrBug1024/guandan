# 掼蛋 AI 竞技场

四个独立 AI、服务端规则裁判、Vue 3 + TypeScript + Vite 界面、Three.js Q 萌角色、LangGraph 决策流水线，以及可供 OBS / 官方直播伴侣采集的直播画面。

## 本地运行

需要 Node.js 22+（本项目在 Node 24 验证）。

```powershell
npm install
Copy-Item .env.example .env
npm run dev
```

已有 `.env` 时直接编辑，不要覆盖现有 Key。打开 http://127.0.0.1:5173/studio 。默认四个内置策略选手，无需 API Key，点击「开始对局」即可。

```powershell
npm test
npm run build
npm start
```

生产构建后访问 http://127.0.0.1:3001 。开发模式和生产模式不要同时占用 3001 端口。当前已安装依赖并验证构建，`package-lock.json` 固定解析版本。

## 四个模型怎么配置

先暂停对局，在「模型配置」逐座位选择来源，可混搭内置策略与独立选手模型。

| 类型        | 地址                                              | Key             | 决策形式                                                   |
| ----------- | ------------------------------------------------- | --------------- | ---------------------------------------------------------- |
| 内置策略    | 无                                                | 无              | 合法动作、手牌结构、队友位置启发式                         |
| OpenAI 兼容 | 服务商 Base URL，例如 `https://api.openai.com/v1` | `.env` 环境变量 | `POST /chat/completions`，输出 `{"choice":0,"reason":"…"}` |

模型名称必须填写你购买服务的实际 model ID。界面填写的是环境变量名称，**不要把 Key 本身填进界面**。

```dotenv
OPENAI_API_KEY=你的实际Key
DEEPSEEK_API_KEY=你的实际Key
JEV_API_KEY=JEV个人访问Key
```

例如某个座位使用 DeepSeek：地址填写其官方 OpenAI 兼容 Base URL、model 填服务商实际 ID、Key 环境变量填 `DEEPSEEK_API_KEY`。修改 `.env` 后重启服务。点击「测试连接与决策」会真实调用一次模型，使用随机的测试手牌。

JEV 是选手可调用的辅助工具，不是第五个选手，也不替代四个模型。在每个选手配置中勾选「允许选手调用 JEV 辅助决策」，填写 MCP URL 和 Key 环境变量名。模型主动请求工具后，后端通过 MCP 获取建议并交回该选手；最终出牌由选手模型再次选择并由裁判校验。仅传本人手牌、公开信息和合法候选，模型不能指定任意 MCP 工具或读取其他选手手牌。原生 function calling 不兼容的网关可使用 JSON 工具请求回退。

本机已绑定桃桃 / MiniMax-M3、蓝莓 / kimi-k2、团子 / glm-5.3-flash、芒果 / gpt-5.6-luna，接口均为 `https://model.rhzy.ai/v1`。凭证分别为 `MINIMAX_API_KEY`、`KIMI_API_KEY`、`GLM_API_KEY`、`QWEN_API_KEY`，JEV 为 `JEV_API_KEY`。已使用提供的凭证真实验证四个模型及 MCP 工具链。模型可自主决定不咨询 JEV。Kimi 使用接口默认温度；MiniMax、Kimi、Qwen 请求关闭扩展思考以适配实时出牌。

JEV 请求：

```json
{
  "situation": "本人手牌、公开局势、合法候选动作的JSON",
  "questions": [
    {
      "type": "choice",
      "question": "哪个合法动作最有利于我方合作获胜？",
      "options": ["0: 三带二 …", "1: 不出"]
    }
  ]
}
```

已观察到的返回结构：`{"model":"jev-omni-bf16","results":[{"choice":"2: 对子A","probabilities":{"0: 不出":0.046,"1: 对子4":0.410,"2: 对子A":0.544},"confidence":0.544}]}`。模型能做分类不意味着它已经掌握掼蛋最优策略，策略质量需用对局结果评估。

## 决策与规则

详见 [规则约定](docs/rules.md) 和 [架构与上线说明](docs/architecture.md)。服务端生成合法候选 → 模型选择 → 再校验 → 规则引擎提交 → SSE 广播。外部模型只看到自己的手牌、对手手牌数量和公开历史。

为控制上下文与分类成本，模型最多看到 41 个经过本地策略排序的候选；相同点数、等价花色与同副牌复制牌会归一化，保留天然牌／逢人配的不同分配及同花顺语义。单次 HTTP / MCP 请求限时 45 秒；工具调用需要多次请求，因此完整决策可能超过 45 秒。上游 5xx 最多重试一次。最终超时、接口错误或非法结果明确记录为「本地兜底」。内置策略和兜底不是大语言模型。

「下一局」执行升级及自动贡还牌。还贡使用合法范围内最小牌，是确定性裁判流程，当前没有让模型单独选择还贡。默认连续对局：局末结算停留 8 秒，自动贡还与发牌，然后继续。结算期间点暂停可取消续局；单步测试不会触发自动续局。可在管理配置中关闭，打过 A 后停止。模型配置持久化到 `data/agents.json`，每局结束自动保存 `data/replays/`。对局暂未支持进程重启恢复，重启会新开比赛。

## 直播

控制台：http://127.0.0.1:5173/studio

横屏直播：http://127.0.0.1:5173/arena?broadcast=1

竖屏直播：http://127.0.0.1:5173/arena?broadcast=1&layout=portrait

生产模式把端口改为 3001。直播页面仅显示赛事素材，与控制台共用服务端对局，刷新不会重发牌。

1. 在 OBS 添加「浏览器」来源：横屏 1920×1080 或竖屏 1080×1920，30 FPS。来源 URL 填上述直播链接。
2. 抖音 / 快手 / 视频号通过官方直播伴侣、官方直播工具捕获浏览器／OBS 画面。账号获得平台推流地址与权限后，才可在 OBS 使用自定义 RTMP。
3. 在控制台配置行动间隔，直播建议 3.5–6 秒。可开启当前控制页的浏览器语音解说，OBS 捕获桌面音频；依赖系统中文语音包。独立直播页不自动播音，避免多页面重复音频。
4. 多平台同时直播需每个平台开播权限、各自官方工具或已获授权的推流地址，并确保编码性能、上行带宽与平台要求。

项目**没有内置平台登录、自动领取推流码或自动开播**。这些需要账号授权及具体平台可用接口。当前交付的是实际可采集的直播画面及接入流程。

官方资料：[OBS 浏览器来源](https://obsproject.com/browser-source)、[抖音直播伴侣](https://streamingtool.douyin.com/)、[快手直播伴侣](https://live.kuaishou.com/live-partner)、[视频号助手](https://channels.weixin.qq.com/)。

## 调试与回放

「手牌与回放」可查看四家手牌、导出本局初始手牌和逐步状态、导入同格式 JSON 后使用时间轴查看。完整回放有私有手牌，不适合直播途中公开。只读观众接口只公开近侧 0 号选手的手牌；其他三家的手牌不进入观众数据。受控调试接口才返回四家手牌。AI 模型仍各自只读取自己的手牌。

默认只绑定本机。若要在局域网使用，设置 `HOST=0.0.0.0` 和强 `CONTROL_TOKEN`，控制台填同一口令。后端拒绝在未设置口令时对外监听。生产远程部署建议通过 HTTPS 反向代理，并单独保护控制台；详见架构文档。开发 Vite 默认不对外开放。

## 已验证与剩余边界

- 规则单测覆盖发牌、级牌、逢人配、顺子／同花顺／连对／钢板、炸弹比较、接风、升级、贡还牌、隐藏信息、非法动作及完整策略对局。
- Vue / 服务端 TypeScript 类型检查和生产构建；本机浏览器验证 Three.js 渲染及实时对局。
- Q 萌角色为 Three.js 程序建模，含坐姿、呼吸、眨眼、思考看牌、理牌微动、伸手出牌、弧线落牌、不出摇头与出完庆祝动作；视线随当前出牌者与落牌转移，轮到自己看手牌；近侧在炸弹或出完牌后短暂回应观众，思考压力触发抬手动作。尚未使用专业美术模型、骨骼动作、表情 blendshape 或口型。
- 四个外部模型和 JEV MCP 已配置并实际调用；上游网关偶有 500 或超时，失败会明确显示本地兜底。未以任何平台账号实际开播。
- 当前单房间、单进程、内存对局；没有多租户、付费系统、弹幕接口或生产级断线恢复。可运行首版与商用长期无人值守系统需要区分。

## 页面与观战视角

- `/studio` 是上级赛事工作室；子路由 `/studio/models` 配置选手，`/studio/broadcast` 管理直播素材，`/studio/replays` 调试与导入回放。
- 在大厅点击「开始对局」，或配置页点击「保存并开始对局」，进入独立 `/arena` 页面。比赛页不显示侧栏与配置表单，动态面板可折叠。
- `/arena` 跟随近侧桃桃的肩后视角：0 号背向观众、1 号在左侧朝内、2 号在对面、3 号在右侧朝内。近侧真实手牌可见，其他选手只展示牌背和张数。
- 椅子、坐垫、扶手、桌腿、皮革边沿、木质桌圈、毡面纹理、阴影和个人杯具共同建立空间感。
- 返回工作室按钮会暂停比赛，配置修改不与进行中的模型决策争抢状态。直接访问观战链接不会自动开局。
- 旧的 `/?broadcast=1` 地址会重定向到 `/arena?broadcast=1`。

新增验证：`npm test` 覆盖观众只获得单家手牌；运行中的服务可执行 `python tests/smoke.py` 和 `python tests/continuous.py`，后者真实验证局末 8 秒、暂停取消续局、下一局发牌与自动恢复。集成测试要求四个内置策略选手，且未设置控制口令。

镜头进一步拉近，牌桌和角色同比例增大。桌面按当前牌墩累积公开出牌，带稳定的轻微旋转、错位和层叠；一墩结束清桌。刷新或回放跳转会从对应历史恢复牌墩，不残留未来的牌。

角色渲染采用细分曲面、微表面凹凸、低强度环境反射与柔和高光；耳朵内外层共同变换，眼睛高光跟随眼神及眨眼。腿脚独立于上半身转动，降低脚穿地面的风险；牌扇抬高且减少厚度偏移，桌面各手牌按厚度逐层累计，避免相互穿插。椅背、桌沿和出牌伸手距离留有间隙；该实现仍是受限姿态动画，并非全身物理碰撞系统。
