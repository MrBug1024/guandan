# AI 博弈实验项目整体优化分析

## 结论

项目的核心产品不是“看 AI 打掼蛋”，而是把掼蛋作为多人协作、信息不完整、决策连续且结果可观察的实验环境，研究 AI 在指定情境下如何选择、如何与搭档互动，以及行为在重复试验中是否稳定。直播是实验的公开表达方式；实验设计、运行记录和结果分析才是产品内核。

因此，产品应当明确分成两个界面和两种任务：

- **观众直播**：仅优化移动端，竖屏和横屏都能看清座位、当前出牌、行动方、牌数和少量即时数据。使用固定的 2D 牌桌，不把 3D 镜头控制作为理解牌局的前置条件。
- **实验工作台**：桌面端优先，移动端可查看。管理者能看到当前运行状态、决策过程、模型耗时与异常、单局和历史实验结果，并能区分实测指标、推导指标和尚未采集的数据。

## 对运营方案的转化

《AI博弈实验直播IP化运营方案_2026-10-10》提出了持续更新的课题制内容、单场约 12-15“把”、累计 40-50 手的内容节奏，也提出搭档协作、提示词风险偏好、记忆/上下文退化等课题，以及观众投票、提示词参与、期望值/实际决策、协作指数和风格雷达等内容形式。

这些方向可以转成稳定的节目模板：

1. **本期问题**：一句可证伪的问题，例如“只改变搭档提示词中的协作约束，搭档领先时的跟牌选择会怎样变化？”
2. **实验条件**：对照组和实验组的模型、提示词版本、参数、牌局种子及其他差异都要记录。每次只改变要研究的主要因素。
3. **观察窗口**：定义观测事件和上下文，例如“搭档已领先、轮到本方、手中存在合法压制牌”。只统计事件数量不足以说明决策好坏。
4. **结果回看**：把关键时刻、原始决策、当时可选动作、最终牌局结果和条件版本放在一起，支持直播复盘与后台复核。
5. **重复试验**：单场直播是内容单元，不等于统计结论。结论需要跨牌局、跨种子或跨重复运行汇总，并展示样本量与不确定性。

运营方案里的“把”“手”“局”需要在后台和节目脚本中统一定义。当前服务端以 `round` 标识归档单元；如果栏目口径与代码口径不同，应使用独立的展示字段，避免把节目时长、牌局轮次和单次牌局混成一种计数。

## 当前可观测性边界

现有系统保存实际决策、行动来源、耗时、错误/兜底、动作后的牌局帧和已归档牌局。因此，本轮可以直接展示：

- 决策数、由外部模型负责的席位决策事件数、裁判强制动作数、兜底数及兜底率。席位决策事件不等同于底层 HTTP 请求数；重试和工具调用次数目前没有被逐次记录。
- 平均值、中位数、P95 决策耗时，按座位/模型拆分的耗时和动作数量。
- 出牌、过牌等已执行动作分布，以及搭档已领先时的原始选择记录。
- 当前对局状态与历史归档牌局的筛选、详情和回放入口。

候选记录目前是分来源、有限度的：外部模型的候选短名单、最终选择与公开理由会由管理员接口保存；内置启发式只记录合法动作数量和规则说明，不保存每个动作的完整牌面排序；强制动作不需要虚构候选排名。当前仍没有候选动作估值、独立评估器结果、逐次重试/工具轨迹或完整模型输入快照。因此，不能据此声称已测得“最优动作概率”“决策错误率”“偏离最优值”“幻觉率”或有方向性的“协作质量/协作指数”。搭档领先时的过牌/压制只能先作为**行为观察**展示；同一行为在不同牌型、剩余牌、队友策略和胜率局面下含义不同。

“期望值 vs 实际决策”只有在定义并版本化独立的评估器之后才能上线。评估器需要对当时完整可见状态和合法动作集合进行计算，记录候选动作价值、所用算法/版本及不确定性；它是明确的参考基准，不应包装成客观真理。风格雷达也应先定义可复核的行为维度及归一化方法，再决定是否展示。

## 本轮实现方向

### 观众直播

公开观看路由以移动端 2D 棋牌桌为主场景，不再加载 Three.js 场景。牌桌保留清晰的绿毡与桌沿、四方座位、AI 头像、牌数、当前轮牌面和观察席手牌；AI 的决策说明、公开信息依据与对手意图推测放在牌桌下方的战术栏，用户首先看见对局，再顺势理解策略。公开推测必须区分模型输出、规则推演与可核验事实，不展示伪造的“内心独白”。

布局按竖屏和横屏分别组织。桌面访问也显示移动直播版式，而不是继续扩展成需要鼠标控制的 3D 观战页。参考提供的掼蛋/麻将截图时，借用的是牌桌信息层级和牌面可读性，不沿用金币、倍率、下注等商业化视觉暗示。

### 实验工作台

管理端优先适配桌面，实验总览按“运行控制、课题、关键指标、最近行动、决策拆解、队伍信号”组织；独立的 2D 对局控制台同时可用于管理者操作和实时观察。历史页从归档索引读取课题摘要和样本统计，按牌局复核决策轨迹、候选短名单和上下文，并可进入逐步回放。历史索引只返回统计摘要，完整牌局详情仍走受保护的管理接口。

当前总览上的搭档反应是原始计数，不计算主观质量分。管理员决策拆解显示已保存的外部模型候选短名单；启发式动作只标出合法动作集合与固定规则，不伪装成模型排序。候选价值仍暂未采集，页面不会把描述性数据误读成决策准确率。

## 建议的数据与实验协议

后续将“直播状态”升级为可复现实验记录，建议至少有以下实体：

- **实验/场次**：研究问题、假设、条件组、开始结束时间、实验协议版本、是否直播。
- **运行快照**：模型提供方和准确模型标识、提示词版本或哈希、采样参数、工具配置、代码版本、牌局种子。
- **决策事件**：观察状态、合法动作 ID 集合、原始模型输出、解析后的动作、动作来源、耗时、错误与兜底原因。原始提示词和敏感内容仅后台可见。
- **候选评估**：如启用独立评估器，记录每个候选动作的估值、评估器版本、方法和置信/不确定信息，并与实际选择分开存储。
- **结果摘要**：队伍结果、级牌变化、结束原因、关键事件，以及该结果所属的实验条件。

比较提示词、模型或策略时，先对相同牌局条件/发牌种子做匹配对照，再跨多个种子重复；牌局随机性和模型采样随机性要分开记录。展示每组样本数、分布和区间，不只展示均值或单局胜负。是否固定样本数应由小规模试跑得到的波动与目标差异决定，而不是把一场直播的局数直接当作充分证据。一项多智能体评估研究观察到重复运行的时间/轨迹差异，并将重复运行、轨迹记录和延迟/失败等系统信号列为可靠评估的重要组成部分；单次实验应被标注为观察，不应夸大为普遍结论。

针对“搭档协作退化”课题，可先把主要结果定义为特定上下文下的行为率，例如“搭档已领先且本方有合法压制牌时，选择过牌的比例”；同时分层记录剩余手牌、合法动作、队友是否报单、回合阶段及最终队伍结果。该指标仍是行为率。只有另有规则化效用函数或独立评估器，才能讨论其相对代价。

观众投票和提示词参与很适合做节目互动，但可能改变 AI 的输入或实验条件。建议把互动输入做成显式、带版本的实验因素，预先设置范围与生效时间；不能在同一组结果里混合未记录的观众改词和固定条件对照。

## 建议实施顺序

1. **先完成观看与复盘闭环**：移动直播、实时实验总览、历史牌局摘要与详情，并确保公开页不暴露完整手牌或管理数据。
2. **完善实验元数据**：创建实验主题、对照条件、提示词/模型/参数快照和随机种子；建立一个课题的可重复运行流程。
3. **扩展决策候选记录**：外部模型短名单已开始留档；下一步补全当时公开观察快照、提示词/参数版本、解析与兜底步骤，以及逐次重试/工具调用；如果要计算动作价值，再接入版本化评估器。
4. **做跨运行统计**：支持配对条件比较、分层分析、样本数和不确定性呈现。此后再决定协作指数、风格雷达等综合表达。
5. **栏目化和观众参与**：将每期的问题、对照组、关键时刻、阶段性结果沉淀为可复用节目模板，并把互动输入纳入实验日志。

本轮实现覆盖观看、控制、基础决策留痕与归档复盘闭环，并保留模型候选牌面和公开战术假设的来源标记；它还不是完整的实验编排或因果统计平台，课题条件组、可复现实验种子和跨场次配对分析仍待建设。
