# 服务器更新：直播解说与动态面板同步

> 此文档记录先前版本。管理员登录和移动观战更新已替代控制口令与旧直播地址，请部署 AI 按 [最新更新文档](admin-mobile-update.md) 执行。

适用站点：https://gd.rhzy.ai 。仓库：https://github.com/MrBug1024/guandan 。

## 更新行为

- 控制页 `/arena` 操作“直播解说”和“对局动态”，由后端通过 SSE 同步到所有观战页。
- 直播页使用 `/arena?broadcast=1`（竖屏附加 `&layout=portrait`），播放解说；控制页保持静音。
- 直播页首次启用声音，点击“开启直播声音”允许浏览器播放。开启后按钮隐藏；重新加载页面可能需要再次点击。OBS 采集浏览器声音仍需启用相应音频源。
- 动态面板由控制页统一展开、关闭，直播页隐藏关闭按钮。
- 设置对新连接的观战页同样生效；服务重启后默认关闭解说和动态面板，需要在控制页重新开启。

## 给部署 AI 的操作步骤

1. 找到现有项目目录、进程管理方式及反向代理配置。暂停当前对局，按现有方式备份 `.env`、`data/` 和当前 Git 提交。重启会结束内存中的当前比赛。
2. 确认工作区没有未处理修改，再更新仓库 `master` 分支；不要覆盖服务器的 `.env`、`data/agents.json` 或录像。
3. 在项目目录执行：

```sh
git pull --ff-only origin master
npm ci
npm test
npm run build
```

4. 使用原有 PM2、systemd 或容器管理方式重启 Node 服务。此项目生产启动命令为 `npm start`，默认端口 3001。必须同时更新前端构建和后端，不能只上传 `dist/`。不需要修改现有域名或端口。
5. 确认 `https://gd.rhzy.ai/api/health` 返回 `ok: true`。反向代理 `/api/events` 必须关闭响应缓冲并允许长连接；确认浏览器收到 SSE 更新。清理旧构建缓存并重新加载控制页与直播页。

仓库现已包含 Coolify 部署文件 `deploy/Dockerfile`。如果现有部署使用 Coolify，应保持构建上下文为仓库根目录，Dockerfile 路径为 `deploy/Dockerfile`，从最新 `master` 重新构建部署；镜像构建已执行依赖安装和前后端构建，无需另外覆盖 `dist/`。保留 Coolify 中的环境变量，并确认 `/app/data` 有持久化卷，否则更换容器会丢失模型配置和录像。若数据尚未持久化，先备份旧容器 `/app/data`，再迁移到卷。Dockerfile 已安装 curl 以支持 Coolify 健康检查，请勿撤回该已有修复。

## 配置与凭证

沿用现有服务器 CONTROL_TOKEN，所有写操作需要 `Authorization: Bearer <CONTROL_TOKEN>`。不要在仓库、文档、截图或日志中记录实际口令或 API Key。

所有模型 Base URL：`https://model.rhzy.ai/v1`。

| 座位 | 模型 | 服务端环境变量 |
| --- | --- | --- |
| 桃桃 | MiniMax-M3 | MINIMAX_API_KEY |
| 蓝莓 | kimi-k2 | KIMI_API_KEY |
| 团子 | glm-5.3-flash | GLM_API_KEY |
| 芒果 | gpt-5.6-luna | QWEN_API_KEY |

四个模型均可调用 JEV 辅助工具，MCP 地址 `http://10.0.10.2:8019/mcp`，凭证环境变量 `JEV_API_KEY`。JEV 不能替代任何选手。这个地址是内网地址：部署 AI 必须从服务器确认其路由和连通性；本地可访问不能证明服务器可访问。请保留现有内网访问方式，不要直接公开内网服务。

2026-10-01 线上真实连接测试：MiniMax-M3 成功（4152ms）、kimi-k2 成功（5638ms）、gpt-5.6-luna 成功（8327ms）；glm-5.3-flash 返回连接测试失败，具体原因未确认。成功的模型调用不代表它实际请求过 JEV，需查看一次包含成功工具咨询的决策记录或单独验证 MCP。

## 验收

1. 分别打开控制页和直播页（可使用不同浏览器、电脑，确保验证的是服务器同步而非本机存储）。在控制页使用管理口令。
2. 控制页勾选“直播解说”，直播页出现“开启直播声音”。点击后听到开启提示。开始对局后，直播页播报新出牌，控制页无声音。
3. 关闭解说后直播页立即停止声音。再次开启后恢复新动作解说，不补播历史动作。
4. 控制页打开“对局动态”，直播页同步显示；通过控制页“收起”或面板关闭按钮关闭，直播页同步隐藏。
5. 动态面板开启时另开一个直播页，也应显示；刷新页后状态与服务器一致。
6. 使用正确口令向 `/api/control` 提交 `{"action":"presentation","presentation":{"speech":true,"showFeed":true}}`，响应和 `/api/state` 中的 `presentation` 应一致。不正确口令必须被拒绝。直播页无需管理口令接收状态。
7. 分别测试四个模型，确认 GLM 的凭证、模型 ID、网关支持和超时问题；验证 JEV MCP 连接与工具咨询记录。
8. 完成至少一轮实际比赛，检查出牌、结算、升级、进贡、自动下一局和录像。当前更新未在线上完成这些完整对局验收，不应预先宣称全部正常。

## 回滚

暂停比赛，恢复之前已备份的 Git 提交，重新安装对应依赖并构建，再按原方式重启。保留现有 `.env` 和 `data/`。不要通过删除配置或重建凭证进行回滚。
